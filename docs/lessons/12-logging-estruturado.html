Apresentação

03 min · pré-requisito: aulas 01 a 11

Um pipeline em produção roda sem ninguém olhando. O log é a única coisa que sobra quando alguém pergunta o que aconteceu às três da manhã — e print não serve para isso.

A revisão da aula 04 já tinha encostado nesse assunto: um except que engole linha malformada em silêncio é o pior formato de falha. Esta aula é sobre a metade positiva — o que registrar, em que nível, e num formato que uma máquina consiga filtrar.

O que a aula responde

  • O que exatamente o print não tem;
  • Por que log.info("%s", x) é diferente de log.info(f"{x}") — medido;
  • Como sair de texto para JSON sem instalar nada;
  • O que registrar em cada nível, e o que nunca registrar.
A regra que a aula 09 já preparou

O @dataclass de configuração tem __repr__ automático. Um log.info("config: %s", config) despeja o token no log estruturado, de onde ele vai para o agregador e fica indexado. A atividade 08 é inteira sobre isso.

Tempo estimado

40 min de leitura, 1 h 30 de exercícios.

ConteúdoAula 12 · Atividade 02

O que o print não tem

05 min

A mesma informação, das duas formas. A diferença não é estética.

python
print("extracted 4821 records")

log = logging.getLogger("pipeline.extract")
log.info("extracted %d records", 4821)
log.warning("skipped %d malformed lines", 3)
Saída real extracted 4821 records 02:05:14 INFO pipeline.extract extracted 4821 records 02:05:14 WARNING pipeline.extract skipped 3 malformed lines

Cinco coisas que a segunda tem e a primeira não:

TemServe para
horacorrelacionar com o pico de CPU e com o deploy
nívelfiltrar: mostre só WARNING para cima
origemsaber qual estágio falou, sem grep no código
destino configurávelarquivo, stderr, syslog — decidido fora do código
desligávelbaixar o nível sem editar nada

E uma sexta, que só aparece quando dói: print escreve em stdout. Num pipeline cuja saída é dados — python extract.py > orders.jsonl — cada print de diagnóstico entra no arquivo de dados. O logging escreve em stderr por padrão, justamente por isso.

A configuração mínima
python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)-7s %(name)s %(message)s",
    datefmt="%H:%M:%S",
)
log = logging.getLogger(__name__)

Duas linhas, e o __name__ faz o logger herdar o nome do módulo — é o que produz pipeline.extract na saída sem você escrever isso em lugar nenhum.

basicConfig só em um lugar

Ele configura o logger raiz e só tem efeito na primeira chamada — as seguintes são ignoradas em silêncio (a menos que você passe force=True). Chame no main(), nunca em módulo importado: uma biblioteca que chama basicConfig sequestra a configuração de quem a importa.

ConteúdoAula 12 · Atividade 03

Os cinco níveis

05 min

A parte mecânica é trivial. A difícil é decidir o nível — e é o que separa um log que ajuda de um que ninguém lê.

NívelSignificaNum pipeline
DEBUGdetalhe para investigara query montada, o payload da página 3
INFOo curso normal das coisasestágio começou, 1.000 linhas gravadas, job terminou
WARNINGanormal, mas seguimos3 linhas malformadas puladas, retry na página 7
ERRORuma operação falhouo lote 12 não gravou; o job continua nos outros
CRITICALo programa não continuanão conectou no banco, configuração inválida

A pergunta que decide o nível

"Quem precisa acordar por causa disto?"

  • Ninguém, mas quero ver depois se investigar → DEBUG
  • Ninguém, mas é o registro de que funcionou → INFO
  • Alguém deveria olhar amanhã → WARNING
  • Alguém deveria olhar hoje → ERROR
  • Alguém precisa olhar agora → CRITICAL
Os dois erros que matam a utilidade do log

Tudo em INFO. Se cada registro processado gera uma linha, um job de um milhão de linhas produz um milhão de linhas de log. Ninguém lê, o disco enche, e o WARNING que importava fica soterrado. Registre por lote, não por registro.

Erro em WARNING. "Falhou mas eu continuei" com nível WARNING faz o alerta nunca disparar. Se um lote não gravou, é ERROR — mesmo que o job siga.

Níveis por módulo

python
logging.getLogger("urllib3").setLevel(logging.WARNING)   # cala a biblioteca
logging.getLogger("pipeline").setLevel(logging.DEBUG)    # abre o seu código
Saída realurllib3.connectionpool nível efetivo = WARNING pipeline.extract nível efetivo = DEBUG pipeline nível efetivo = DEBUG

Loggers formam uma árvore pelo ponto no nome. Configurar pipeline alcança pipeline.extract e pipeline.load sem citá-los — e é por isso que getLogger(__name__) vale a pena: ele te dá essa árvore de graça.

Mão na massaAula 12 · Atividade 04

A vírgula que muda tudo

05 min

Duas linhas de log que parecem idênticas. O nível DEBUG está desligado nas duas.

python
class Caro:
    def __init__(self): self.n = 0
    def __str__(self):
        self.n += 1
        return "resultado caro"

c1, c2 = Caro(), Caro()
logging.getLogger().setLevel(logging.INFO)   # DEBUG desligado

log.debug("f-string: %s", f"{c1}")
log.debug("lazy: %s", c2)
Prever antes de rodar
Sua resposta fica salva neste navegador.
saída real
com f-string, __str__ chamado 1x  |  com %s lazy, 0x  (nível DEBUG desligado)

A f-string é avaliada antes de log.debug ser chamado — o Python monta a string, e só depois o logging decide jogá-la fora. Com %s e o argumento separado por vírgula, a formatação só acontece se algum handler for de fato emitir.

Num laço quente, isso é a diferença entre pagar a formatação um milhão de vezes por nada e não pagar.

timeit — nível desligado, 100.000 chamadas
log.debug("row %s ok", x)      221 ns
log.debug(f"row {x} ok")       273 ns   -> 1.2x

Aqui o objeto é um inteiro, então a diferença é modesta — 1,2×. Ela explode quando o argumento é caro: um json.dumps(payload), um repr de DataFrame, uma consulta. Com %s, nada disso roda.

A regra, e a saída de emergência

Use sempre log.debug("msg %s", valor). Quando o argumento for realmente caro de produzir, proteja também a produção dele: if log.isEnabledFor(logging.DEBUG):.

O efeito colateral escondido

Repare no que este exemplo mostra de passagem: a f-string chamou __str__, que incrementou um contador. Se o seu __repr__ tem efeito colateral — conta acesso, consome um iterador, faz lazy load —, o log muda o comportamento do programa dependendo do nível. É um bug que só existe em produção.

ConteúdoAula 12 · Atividade 05

Do texto para o JSON

06 min

Log em texto é legível por gente e péssimo para máquina. "Quantos lotes falharam ontem, por tabela?" vira uma expressão regular frágil.

Log estruturado resolve isso: cada linha é um objeto com campos. E não precisa de biblioteca — um Formatter de vinte linhas basta:

python
class JsonFormatter(logging.Formatter):
    """Render each record as one JSON object per line."""

    def format(self, record: logging.LogRecord) -> str:
        payload = {
            "ts": self.formatTime(record, "%Y-%m-%dT%H:%M:%S"),
            "level": record.levelname,
            "logger": record.name,
            "msg": record.getMessage(),
        }
        payload.update(getattr(record, "context", {}))
        if record.exc_info:
            payload["error"] = self.formatException(record.exc_info).splitlines()[-1]
        return json.dumps(payload, ensure_ascii=False)
python
log.info("batch loaded", extra={"context": {"batch": 7, "rows": 1000,
                                            "table": "orders", "ms": 41.2}})
try:
    1 / 0
except ZeroDivisionError:
    log.error("batch failed", exc_info=True, extra={"context": {"batch": 8, "rows": 1000}})
Saída real{"ts": "2026-09-06T02:05:14", "level": "INFO", "logger": "pipeline.load", "msg": "batch loaded", "batch": 7, "rows": 1000, "table": "orders", "ms": 41.2} {"ts": "2026-09-06T02:05:14", "level": "ERROR", "logger": "pipeline.load", "msg": "batch failed", "batch": 8, "rows": 1000, "error": "ZeroDivisionError: division by zero"}

Agora a pergunta do começo é uma linha de jq:

bash
jq -r 'select(.level=="ERROR") | .table' pipeline.log | sort | uniq -c

Os dois detalhes que fazem funcionar

extra= com um dicionário aninhado

O extra do logging cola cada chave direto no LogRecord, e colidir com um atributo existente (message, name, args) levanta KeyError. Passar tudo dentro de uma chave só — extra={"context": {...}} — elimina a classe inteira de colisão.

A mensagem continua estável

"batch loaded" é sempre a mesma string; o que varia vai nos campos. Isso é o que permite agrupar por mensagem no agregador. Uma mensagem que embute o número — f"batch {n} loaded" — produz um grupo por lote e nenhuma contagem útil.

Quando usar structlog

Quando você quiser contexto acumulado: amarrar um run_id no início e ele aparecer em toda linha do job sem ser repassado de função em função. Dá para fazer com logging.LoggerAdapter e contextvars, mas o structlog já resolve. Para começar, o Formatter acima basta.

ConteúdoAula 12 · Atividade 06

Configuração fora do código

05 min

Texto colorido no seu terminal, JSON no servidor, e nada disso decidido dentro dos módulos.

python
LOGGING = {
    "version": 1,
    "disable_existing_loggers": False,
    "formatters": {
        "human": {"format": "%(asctime)s %(levelname)-7s %(name)s %(message)s",
                  "datefmt": "%H:%M:%S"},
        "json": {"()": "pipeline.logging_setup.JsonFormatter"},
    },
    "handlers": {
        "console": {"class": "logging.StreamHandler", "stream": "ext://sys.stderr",
                    "formatter": os.getenv("LOG_FORMAT", "human")},
    },
    "loggers": {
        "pipeline": {"level": os.getenv("LOG_LEVEL", "INFO"), "handlers": ["console"]},
        "urllib3": {"level": "WARNING", "handlers": ["console"]},
    },
    "root": {"level": "WARNING", "handlers": ["console"]},
}

logging.config.dictConfig(LOGGING)

Uma estrutura de dados, aplicada uma vez no main(). LOG_LEVEL=DEBUG na variável de ambiente abre o detalhe sem alterar código nem fazer deploy; LOG_FORMAT=json troca o formato inteiro.

PeçaResponde
Loggerquem falou, e a partir de que nível
Handlerpara onde vai — stderr, arquivo, syslog
Formattercom que cara sai
Filtero que descartar ou enriquecer antes de sair
Em contêiner, escreva em stdout/stderr e pare

Nada de RotatingFileHandler num contêiner: o orquestrador já coleta a saída padrão, e um arquivo dentro do contêiner some no próximo deploy. Escrever em arquivo é para processo que roda numa máquina que você administra.

Bibliotecas não configuram logging

Se você escrever um pacote, use getLogger(__name__) e mais nada — sem basicConfig, sem handler. Quem importa decide. A convenção para não emitir aviso de "no handlers" é logging.getLogger(__name__).addHandler(logging.NullHandler()) no __init__.py.

ConteúdoAula 12 · Atividade 07

O que registrar num pipeline

05 min

Um log útil responde três perguntas sem que ninguém precise abrir o código: rodou?, processou quanto?, deu algum problema?

python — o esqueleto
def run(config: Config) -> None:
    run_id = uuid4().hex[:8]
    log.info("job started", extra={"context": {"run_id": run_id, "since": config.since}})

    with measure("extract"):
        records = source.read(since=config.since)

    report = Loader(sink, batch_size=config.batch_size).run(stages(records))

    log.info("job finished", extra={"context": {
        "run_id": run_id, "rows_in": report.seen, "rows_out": report.inserted,
        "rejected": report.rejected, "seconds": round(report.seconds, 1)}})

Duas linhas de log por execução, e elas bastam para responder as três perguntas. O resto entra por exceção — WARNING para o que foi pulado, ERROR para o lote que não gravou.

Contadores, não eventos

Em vez deRegistre
uma linha por registro processadoo total no fim, e um progresso a cada 100 mil
uma linha por linha malformadaas 5 primeiras, e o total no fim
o payload inteiro da respostao tamanho, o status e a URL
"conectando..." a cada tentativasó as que falharam, com o número da tentativa
O log que mente, da aula 04
python
log.info("extracted %d records", sum(1 for _ in records))   # consumiu o iterador
for record in records:                                       # zero iterações
    warehouse.insert(record)

O log diz extracted 4821 records e a tabela recebe zero linhas. O registro que deveria ajudar a diagnosticar é a causa do problema, e ainda aponta na direção errada. Toda métrica de contagem tem que sair de um contador que o próprio laço incrementa — nunca de uma passada extra sobre um iterador.

Log é a primeira métrica

rows_in, rows_out e rejected numa linha JSON por execução já dão o gráfico de volume ao longo do tempo, e o alerta de "hoje entrou metade do normal". Isso responde a maioria das perguntas de operação antes de existir qualquer ferramenta de métricas.

AtençãoAula 12 · Atividade 08

O que nunca registrar

04 min

Log vai para disco, para o agregador, para o backup do agregador, e frequentemente para um serviço de terceiros. O que entra ali é muito difícil de tirar.

Credenciais

Token, senha, chave de API, string de conexão com senha embutida. E o caminho mais comum não é você escrever log.info(token) — é o __repr__ automático de uma @dataclass de configuração, como a aula 09 avisou. Use field(repr=False).

Dado pessoal

CPF, e-mail, endereço, cartão. Um log com CPF é um banco de dados de CPFs sem controle de acesso. Registre o id interno, que não identifica ninguém fora do seu sistema, ou um hash.

O registro inteiro

log.debug("record: %s", record) parece inofensivo em desenvolvimento. Em produção com LOG_LEVEL=DEBUG ligado para investigar, ele despeja o dataset inteiro no agregador — com tudo que houver dentro.

Segredo dentro de exceção

exc_info=True imprime o traceback com os valores locais em algumas configurações, e a URL com token no query string aparece na mensagem de erro do cliente HTTP. Higienize a URL antes de registrar.

python — duas defesas simples
@dataclass(frozen=True, slots=True)
class ApiConfig:
    base_url: str
    token: str = field(repr=False)        # fora do repr, fora do log


class RedactFilter(logging.Filter):
    """Blank anything that looks like a token in the rendered message."""
    PATTERN = re.compile(r"(token|password|api[_-]?key)=([^&\s]+)", re.I)

    def filter(self, record: logging.LogRecord) -> bool:
        record.msg = self.PATTERN.sub(r"\1=***", str(record.msg))
        return True
O filtro é a segunda linha de defesa

Uma regex nunca vai pegar tudo. A defesa de verdade é não colocar o segredo perto do log: repr=False, URL sem credencial, e revisar o que vai em extra. O filtro existe para o que escapar.

E vale a mesma frase da aula 06: se um segredo vazou para o log e o log foi enviado, rotacione a credencial. Apagar a linha não desfaz nada.

Desafio: o segredo que vaza

desafio

Depois aplique as duas defesas — field(repr=False) e o RedactFilter — e prove com testes que:

O terceiro item é o ponto do exercício
