A aula 05 ensinou a medir. Esta usa a régua o tempo todo: cada estrutura de dados do Python tem um custo diferente para cada operação, e escolher errado é a forma mais comum de um pipeline correto ficar lento.

Você já sabe escrever for, list e dict. O que muda aqui é passar a escolher entre eles pelo custo da operação que você vai fazer mais vezes, e não pelo que veio primeiro à cabeça.

As perguntas que a aula responde com número

  • Por que lista.insert(0, x) é uma armadilha e o que usar no lugar;
  • Quanto de memória você paga por escolher dict em vez de dataclass(slots=True) para representar um registro;
  • Como pegar os 10 maiores de um milhão sem ordenar o milhão.
O que não é esta aula

Não é uma tabela de complexidade para decorar. É a medição de cada caso, com o raciocínio que faz a tabela ser óbvia depois. Se você entender por que o set não fica mais lento quando cresce, não precisa lembrar que ele é O(1).

ConteúdoAula 07 · Atividade 02

list contra set: a mesma pergunta

07 min

"Este id já apareceu?" é a pergunta mais frequente de um pipeline de deduplicação. Feita na estrutura errada, ela é a linha mais cara do programa.

python
xs = list(range(100_000))
st = set(xs)
alvo = 99_999

# a mesma pergunta, duas estruturas
alvo in xs
alvo in st
Saída realx in list (100,000 itens): 591.5 µs x in set (100,000 itens): 0.052 µs -> 11.375x

Onze mil vezes. E o número isolado importa menos que o próximo, que é o da aula 05: meça em três escalas.

timeit — o mesmo teste, entrada crescendo 10x
n=  1,000 | list      5.4 µs | set  0.054 µs
n= 10,000 | list     55.3 µs | set  0.054 µs
n=100,000 | list    575.6 µs | set  0.056 µs

Leia por coluna. A do list multiplica por dez junto com a entrada: é O(n), porque a única forma de saber se um valor está numa lista é olhar item por item. A do set não se move: é O(1).

Por que o set não precisa procurar

Porque ele não guarda os valores em fila. Ele calcula hash(x), transforma o número num endereço, e vai direto nesse endereço conferir. O tamanho do conjunto não muda o cálculo do endereço — daí a reta horizontal.

É o mesmo mecanismo do dict: um set é, para efeitos práticos, um dict só com chaves.

O in que ninguém percebe
python — O(n) dentro de um laço O(n)
vistos = []
for record in records:            # n vezes
    if record["id"] not in vistos:   # cada uma custa O(n)
        vistos.append(record["id"])
        yield record

Isso é O(n²). Com 100 mil registros são cinco bilhões de comparações. Trocar vistos = [] por vistos = set() e append por add resolve — uma palavra de diferença, e o pipeline sai de horas para segundos.

Quando a lista ainda é a resposta certa

Você precisa deUsePor quê
Ordem, repetição, índicelistset não tem nenhuma das três
Perguntar "já vi?"setO(1) contra O(n)
Associar chave a valordictmesmo O(1), com carga
Percorrer uma vez e descartargeneratorO(1) de memória (aulas 02 e 05)
Itens não hasheáveislistset exige __hash__; dict e list não têm
O que não entra num set

Só objetos imutáveis: str, int, tuple de imutáveis, frozenset. Um dict ou uma list levantam TypeError: unhashable type. Para deduplicar registros, use uma chave extraída deles — (r["id"], r["date"]) — e não o registro inteiro.

Mão na massaAula 07 · Atividade 03

Onde está o O(n²)

05 min

Três funções que fazem a mesma coisa: juntar cada pedido ao usuário dele. Uma delas não escala. Ache antes de rodar.

python
def join_a(orders, users):
    for order in orders:
        user = next(u for u in users if u["id"] == order["user_id"])
        yield {**order, "city": user["city"]}

def join_b(orders, users):
    by_id = {u["id"]: u for u in users}
    for order in orders:
        yield {**order, "city": by_id[order["user_id"]]["city"]}

def join_c(orders, users):
    for order in orders:
        for user in users:
            if user["id"] == order["user_id"]:
                yield {**order, "city": user["city"]}
                break
Prever antes de rodar
Sua resposta fica salva neste navegador.

A e C são a mesma função. O next(u for u in users if ...) do A é um laço escrito de outro jeito — ele varre users até achar, exatamente como o for aninhado do C. As duas são O(n·m).

B é O(n+m): paga uma varredura para construir o índice e depois cada busca é O(1). Com 50 mil usuários e 50 mil pedidos, A e C fazem até 2,5 bilhões de comparações; B faz 100 mil operações.

O padrão a memorizar

Toda vez que você procura dentro de um laço, construa um índice antes do laço. Uma linha — by_id = {u["id"]: u for u in users} — troca a complexidade da função inteira. É o mesmo movimento que um banco de dados faz quando cria um índice, e é literalmente o assunto da aula 15.

A pegadinha do A é que ele parece lazy e enxuto. Comprimento de código não tem relação nenhuma com complexidade.

ConteúdoAula 07 · Atividade 04

A lista tem duas pontas e só uma é barata

05 min

Uma list do Python é um vetor contíguo. Acrescentar no fim é quase de graça; inserir no começo obriga a empurrar todo o resto uma casa para a direita.

timeit
n= 1,000 | list.insert(0,x)    0.47 µs | deque.appendleft  0.04 µs -> 12x
n=10,000 | list.insert(0,x)    3.37 µs | deque.appendleft  0.04 µs -> 84x

De novo a mesma leitura: a coluna do deque não se move, a da list cresce com n. Um deque é uma lista duplamente ligada em blocos — ele tem ponteiro para as duas pontas, então as duas custam O(1).

Operaçãolistdeque
append(x)O(1)O(1)
pop()O(1)O(1)
insert(0, x) / appendleftO(n)O(1)
pop(0) / popleftO(n)O(1)
x[i]O(1)O(n)

A última linha é o preço: o deque não tem acesso por índice barato. Ele é a estrutura certa para fila e para janela deslizante, não para acesso aleatório.

Onde isso aparece em ETL

python — janela deslizante com tamanho fixo
from collections import deque

def moving_average(values, window: int):
    """Yield the mean of the last `window` values, in constant memory."""
    buffer = deque(maxlen=window)      # ele mesmo descarta o mais antigo
    for value in values:
        buffer.append(value)
        if len(buffer) == window:
            yield sum(buffer) / window

O maxlen é o detalhe: ao encher, cada append empurra o item mais antigo para fora automaticamente. Sem ele você teria que escrever o descarte à mão — e é aí que aparece o pop(0) que custa O(n).

Fila de tarefas

deque é a fila do collections, e popleft() é O(1). Se você já escreveu fila.pop(0) num laço de processamento, aquilo era O(n²) disfarçado.

ConteúdoAula 07 · Atividade 05

Quanto pesa um registro

07 min

Um pipeline manipula milhões de registros de três campos. A escolha de como representar esses três campos muda o consumo por um fator de dois.

tracemalloc — 200.000 registros de (id, amount, city)
dict              :   47.3 MB
dataclass         :   30.5 MB
namedtuple        :   27.5 MB
tupla pura        :   25.9 MB
dataclass(slots)  :   22.9 MB

Do topo à base, 2,1×. Num pipeline que carrega dez milhões de linhas, é a diferença entre caber e não caber.

Por que o dict é o mais caro

Porque cada dict carrega a própria tabela hash e as próprias chaves. Duzentos mil registros com os mesmos três nomes de campo guardam esses nomes duzentas mil vezes — e a estrutura que permite acrescentar um quarto campo a qualquer momento tem que existir em todos eles.

Uma dataclass normal guarda os atributos num __dict__ por instância, então ainda paga parte disso. Com slots=True, o Python troca o dict por um vetor de posições fixas: os nomes dos campos passam a viver uma vez, na classe.

python
from dataclasses import dataclass

@dataclass(slots=True)
class Order:
    id: int
    amount: float
    city: str

Uma palavra, 52% menos memória que o dict, e de quebra o atributo errado vira erro:

python
order = Order(1, 10.0, "sp")
order.citty = "rj"      # typo
Saída realAttributeError: 'Order' object has no attribute 'citty'

Com dict, record["citty"] = "rj" cria a chave e segue em silêncio — e o campo certo continua com o valor velho. É o mesmo formato de falha da aula 01: nada reclama, e o resultado sai errado.

Como escolher

SituaçãoEscolha
Fronteira do sistema: JSON que chega, JSON que saidict
Registro que atravessa o pipeline, com campos conhecidosdataclass(slots=True)
Registro que precisa ser chave de dict ou entrar num setfrozen=True junto
Milhões de linhas, campos posicionais, só leituratuple ou namedtuple
Schema desconhecido em tempo de escritadict, sem alternativa
O limite do slots

Com slots=True você não pode acrescentar atributos em tempo de execução, e herança múltipla fica restrita. Nenhum dos dois costuma importar num registro de pipeline — mas se o seu código faz setattr dinâmico, o slots vai quebrá-lo, e o erro é claro.

Para saber maisAula 07 · Atividade 06

Por que uma tupla pesa menos que um objeto

04 min

Vale abrir a conta, porque ela explica os cinco números da atividade anterior de uma vez.

Todo objeto Python carrega um cabeçalho fixo: contador de referências e ponteiro para o tipo. Em CPython de 64 bits, 16 bytes. O que muda entre as estruturas é o que vem depois do cabeçalho:

Tupla: cabeçalho + n ponteiros

Tamanho fixo, decidido na criação. Nada de espaço sobrando, nada de nomes. É o piso do que dá para pagar guardando três referências.

Objeto com __slots__: cabeçalho + n ponteiros

Praticamente uma tupla com nomes. Os nomes ficam na classe, uma vez só; a instância guarda só os valores, em posições fixas. Daí ele empatar quase com a tupla e ainda dar acesso por atributo.

Objeto normal: cabeçalho + ponteiro para um __dict__

Some um dict inteiro por instância. O CPython otimiza compartilhando as chaves entre instâncias da mesma classe, e é por isso que a dataclass normal (30,5 MB) não chega ao custo do dict solto (47,3 MB).

dict solto: tabela hash com folga

Uma tabela hash precisa de espaço vazio para não colidir — tipicamente um terço a mais que o necessário. E, sem a otimização de chaves compartilhadas, cada dict guarda a própria cópia da tabela de chaves.

A regra prática

Quanto mais o Python precisa deixar em aberto sobre o objeto, mais ele custa. dict deixa tudo em aberto — nomes, quantidade, tipos — e cobra por isso. slots fecha a quantidade e os nomes. tuple fecha até a identidade dos campos.

E o mesmo raciocínio dá a ponte com a fase 2: um DataFrame do pandas ou uma tabela Parquet fecham também o tipo de cada coluna e guardam os valores lado a lado, sem cabeçalho por item. É por isso que um milhão de inteiros num ndarray ocupa 8 MB e num list de objetos ocupa dezenas.

ConteúdoAula 07 · Atividade 07

Contar coisas

05 min

Contar ocorrências e agrupar por chave são as duas agregações mais frequentes de um pipeline. O collections tem as duas prontas, e a versão pronta é mais rápida.

timeit — contar 200.000 valores em 50 categorias
d[w] = d.get(w, 0) + 1     14.3 ms
defaultdict(int)           13.7 ms
Counter(palavras)           9.7 ms

O Counter ganha porque o laço dele roda em C. Mas a razão principal de usá-lo não é velocidade — é o que ele diz a quem lê:

python
from collections import Counter

por_cidade = Counter(r["city"] for r in records)
print(por_cidade.most_common(5))          # os 5 maiores, já ordenados
print(por_cidade["cidade-que-nao-existe"]) # 0, não KeyError

defaultdict: o agrupador

Counter conta; defaultdict acumula qualquer coisa. É a resposta para o "agrupar sem ordenar" da aula 04:

python
from collections import defaultdict

por_regiao = defaultdict(list)
for record in records:
    por_regiao[record["region"]].append(record)   # sem checar se a chave existe

totais = defaultdict(float)
for record in records:
    totais[record["region"]] += record["amount"]
O defaultdict que cria chave sem você pedir
python
d = defaultdict(list)
if d["norte"]:            # só queria consultar...
    ...
print(dict(d))            # {'norte': []}  <- a chave foi criada

Ler uma chave ausente de um defaultdict cria a chave. Num relatório por região isso inventa regiões vazias que ninguém entende de onde vieram. Para só consultar, use d.get(k) ou k in d.

E lembre da aula 04

defaultdict é O(n) de memória: ele segura tudo antes de responder qualquer coisa. Se a fonte já vem ordenada pela chave, itertools.groupby faz o mesmo agrupamento em O(1) — foi a medição de 0,00 MB contra 11,70 MB do exercício 4.4.

ConteúdoAula 07 · Atividade 08

Top-N sem ordenar tudo

05 min

"Os 10 maiores pedidos do mês" é um requisito banal, e a implementação óbvia faz mil vezes mais trabalho do que precisa.

python — 1.000.000 de valores
sorted(dados, reverse=True)[:10]      323.8 ms   pico  11.4 MB
heapq.nlargest(10, dados)              18.8 ms   pico   0.2 KB

17× mais rápido e 58 mil vezes menos memória. A diferença não é otimização de micro-detalhe: são dois algoritmos diferentes.

sorted resolve um problema maior do que o pedido — ele ordena o milhão inteiro, O(n log n), materializando uma lista nova de um milhão de itens — e depois joga 999.990 fora. O nlargest mantém um heap de dez elementos e percorre a fonte uma vez: O(n log 10), com dez itens na memória.

python
import heapq

# funciona sobre qualquer iterável — inclusive um generator que lê do disco
maiores = heapq.nlargest(10, read_jsonl(path), key=lambda r: r["amount"])
menores = heapq.nsmallest(10, read_jsonl(path), key=lambda r: r["amount"])

Repare que ele aceita um generator. Isso o coloca na lista curta de agregações O(1) de memória da aula 05 — junto com sum, min e max, e ao contrário de sorted e da mediana.

Onde ele deixa de compensar

Quando N se aproxima de n. nlargest(500_000, dados) sobre um milhão é mais lento que ordenar, porque o heap passa a ter meio milhão de elementos. A documentação sugere a regra: para N pequeno use nlargest; para N próximo de n use sorted; para N igual a 1 use max, que é O(1) e mais claro.

ReferênciaAula 07 · Atividade 09

A tabela de custos

04 min

Agora que cada linha foi medida, a tabela deixa de ser decoreba e vira consulta.

Operaçãolistdequeset/dict
acessar por índiceO(1)O(n)—
acessar por chave——O(1)
x in ...O(n)O(n)O(1)
inserir no fimO(1)O(1)O(1)
inserir no começoO(n)O(1)—
remover do meioO(n)O(n)O(1)
percorrer tudoO(n)O(n)O(n)
manter ordenadoO(n log n)——

As três perguntas que resolvem a escolha

  1. Qual operação eu faço mais vezes? Otimize essa, ignore as outras.
  2. Preciso de ordem? Se não, quase sempre é set ou dict.
  3. Preciso disso tudo na memória ao mesmo tempo? Se não, é generator — nenhuma linha desta tabela se aplica.
O que quase sempre está errado

Uma list usada como conjunto (if x in lista) e uma list usada como fila (lista.pop(0)). São os dois O(n) escondidos mais comuns em código Python de dados, e os dois têm substituto de uma palavra.

Antes de trocar qualquer coisa

Meça. Um in sobre uma lista de dez itens não é problema de ninguém — trocar por set ali só deixa o código mais estranho. A tabela vale quando n cresce, e "cresce" é uma afirmação que precisa de número, como na aula 05.

Desafio: o perfil de uma estrutura errada

desafio

python
def enrich(orders, users, blocked_ids):
    """Attach the user's city and drop blocked users, newest first."""
    out = []
    for order in orders:
        if order["user_id"] in blocked_ids:        # blocked_ids e uma list
            continue
        for user in users:                         # users e uma list
            if user["id"] == order["user_id"]:
                out.insert(0, {**order, "city": user["city"]})
                break
    return out
